Ubuntu WSL và PowerShell • MySQL Workbench • XAMPP

Tài liệu dành cho máy Windows đã cài Ubuntu WSL, Oracle MySQL Server, MySQL Workbench và XAMPP. Bạn sẽ cấu hình dự án thủ công, xem được database trong Workbench và bật hoặc dừng website khi cần. Không cần chạy file BAT.

Chọn Ubuntu WSL hoặc PowerShell ở thanh công cụ. Mỗi bước chỉ chạy nhóm lệnh của terminal đang dùng. Các bước SQL trong Workbench và các file cấu hình dùng chung.

01

Trước khi bắt đầu

Thành phầnVai trò
XAMPP Apache và PHPChạy website và xử lý PHP trên Windows
Oracle MySQL ServerLưu database và chạy dưới dạng dịch vụ Windows
MySQL WorkbenchCông cụ kết nối, xem, tạo và sao lưu database
Ubuntu WSL hoặc PowerShellTerminal để nhập lệnh

Dòng MySQL trong XAMPP sử dụng MariaDB. Dự án này dùng Oracle MySQL riêng, nên chỉ bật Apache trong XAMPP. Đóng Workbench không dừng MySQL Server. [1]

Thông số mẫu trong tài liệu

Cùng thư mục đó trong WSL/mnt/c/Projects/pixelnote

3307 không phải cổng bắt buộc. Nếu máy mới đã cấu hình MySQL ở 3306, giữ 3306 và thay 3307 trong kết nối Workbench, config.local.php và các lệnh kiểm tra cổng. Tên dịch vụ MySQL cũng phải lấy theo máy thực tế.

Cài mới: thực hiện mục 02 đến 08. Mang dữ liệu cũ sang: đọc mục 10 trước; nhập bản sao lưu thay bước tạo bảng và dữ liệu mẫu. Chỉ sao chép mã nguồn sẽ không mang theo database và ảnh đã tải lên.

Các lệnh bên dưới giả định XAMPP nằm tại C:\xampp. Nếu khác, sửa đường dẫn tương ứng. Dự án đặt ở ổ Windows để Apache của Windows truy cập trực tiếp; không cần cài thêm PHP hay MySQL trong Ubuntu.

02

Chuẩn bị mã nguồn và terminal

  1. Giải nén PixelNote-XAMPP-MySQL.zip vào C:\Projects.
  2. Kiểm tra có file C:\Projects\pixelnote\public\index.php. Tránh lồng thêm một thư mục pixelnote ngoài ý muốn.
  3. Mở VS Code → File → Open Folder → chọn thư mục pixelnote.
  4. Chọn Terminal → New Terminal. Bấm mũi tên cạnh dấu cộng trong terminal rồi chọn Ubuntu WSL hoặc PowerShell.

Nếu VS Code đang mở ở chế độ Remote WSL, có thể dùng cửa sổ Windows Terminal riêng để mở PowerShell trên Windows. Hai terminal vẫn thao tác cùng thư mục dự án.

Ubuntu WSL
cd /mnt/c/Projects/pixelnote
pwd
ls public/index.php database/schema.sql scripts/install.php
PowerShell
Set-Location -LiteralPath 'C:\Projects\pixelnote'
Get-Location
Get-Item .\public\index.php, .\database\schema.sql, .\scripts\install.php

Kết quả cần đạt: đứng đúng thư mục và tìm thấy cả ba file. Các lệnh dùng đường dẫn tương đối ở phần sau đều chạy từ thư mục này.

Kiểm tra WSL nếu cần

Ubuntu WSL
wsl.exe --list --verbose
uname -r
PowerShell
wsl.exe --list --verbose

Trong Ubuntu dùng wsl.exe. Lệnh wsl không có đuôi exe có thể gọi nhầm chương trình Linux khác. Trong WSL, ổ C tương ứng /mnt/c, ổ E tương ứng /mnt/e. Khi gọi PHP của Windows, wslpath -w chuyển đường dẫn file sang dạng Windows. [2]

Nếu dự án ở E:\Projects\pixelnote, dùng /mnt/e/Projects/pixelnote trong Ubuntu và sửa đường dẫn Apache ở mục 07. Không sao chép phần dấu nhắc như PS C:\...> hoặc ten@may:...$ vào lệnh.

03

Kiểm tra MySQL Server và kết nối Workbench

Hướng dẫn này sử dụng MySQL đã được cấu hình thành dịch vụ Windows. Kiểm tra tên và trạng thái dịch vụ:

Ubuntu WSL
powershell.exe -NoProfile -Command "Get-Service -Name '*MySQL*' | Format-Table Name,Status,DisplayName"
PowerShell
Get-Service -Name '*MySQL*' | Format-Table Name,Status,DisplayName

Ghi lại tên trong cột Name, ví dụ MySQL80 hoặc MySQL84. Nếu trạng thái Stopped, mở PowerShell trên Windows bằng Run as administrator, rồi chạy lệnh sau với đúng tên dịch vụ.

PowerShell Windows · Run as administrator
Start-Service -Name 'MySQL80'
Get-Service -Name 'MySQL80'

Start và Stop dịch vụ thường cần quyền quản trị Windows. sudo trong Ubuntu không cấp quyền quản trị Windows. Có thể mở ứng dụng Services trên Windows, chọn dịch vụ MySQL tương ứng rồi Start. [3]

Nếu không thấy dịch vụ, kiểm tra MySQL Server đã thực sự được cài và hoàn tất cấu hình Windows Service trong bộ cài MySQL hoặc MySQL Configurator. Chỉ cài Workbench là chưa đủ. Nếu máy đang dùng instance chạy thủ công, cần xác định instance đó trước khi tạo thêm dịch vụ.

Tạo kết nối trong Workbench

Mở MySQL Workbench → dấu + cạnh MySQL Connections → nhập:

TrườngGiá trị
Connection NamePixelNote Local
Connection MethodStandard TCP/IP
Hostname127.0.0.1
Port3307 hoặc cổng thực tế
Usernameroot
PasswordMật khẩu root đã đặt trên máy mới

Bấm Test Connection, nhập mật khẩu nếu được hỏi, bấm OK rồi mở kết nối. Trong SQL tab, chạy:

MySQL Workbench · SQL
SELECT VERSION() AS mysql_version,
       @@port AS mysql_port,
       @@datadir AS data_directory;

Kết quả cần đạt: kết nối được đến Oracle MySQL, không phải MariaDB; ghi lại cổng thực tế. Mã nguồn đã được kiểm thử với MySQL 8.0; tên MySQL80 trong tài liệu là ví dụ, không phải tên bắt buộc. [4]

04

Kiểm tra PHP và thư mục lưu dữ liệu

Chạy tại thư mục dự án:

Ubuntu WSL
/mnt/c/xampp/php/php.exe -v
/mnt/c/xampp/php/php.exe --ini
/mnt/c/xampp/php/php.exe -m | grep -E 'PDO|pdo_mysql|mbstring|fileinfo'
mkdir -p storage/uploads storage/logs storage/sessions storage/tmp
PowerShell
& 'C:\xampp\php\php.exe' -v
& 'C:\xampp\php\php.exe' --ini
& 'C:\xampp\php\php.exe' -m | Select-String 'PDO|pdo_mysql|mbstring|fileinfo'
New-Item -ItemType Directory -Force -Path .\storage\uploads, .\storage\logs, .\storage\sessions, .\storage\tmp | Out-Null

Kết quả cần đạt: PHP 8.2 hoặc phiên bản tương thích mới hơn; có đủ PDO, pdo_mysql, mbstring và fileinfo. Các ví dụ gọi trực tiếp PHP của XAMPP để tránh nhầm PHP khác trong PATH.

Nếu thiếu extension, mở file php.ini tại dòng Loaded Configuration File trong kết quả lệnh --ini. Với XAMPP mặc định thường là C:\xampp\php\php.ini. Bỏ dấu ; trước ba dòng sau nếu đang bị tắt; không thêm dòng trùng:

Các dòng trong php.ini
extension=pdo_mysql
extension=mbstring
extension=fileinfo

Lưu file rồi chạy lại lệnh kiểm tra. Nếu Apache đang chạy, Stop rồi Start Apache để nạp cấu hình. Khi CLI có extension nhưng web vẫn báo thiếu, kiểm tra file qua XAMPP → Config cạnh Apache → PHP php.ini.

Trong PowerShell, dấu & trước đường dẫn thực thi đặt trong nháy là cần thiết. Trong Ubuntu dùng đường dẫn /mnt/c/.../php.exe như ví dụ.

05

Tạo database và các bảng trong Workbench

Thực hiện bằng kết nối root trong Workbench. Các lệnh sau dành cho database mới chưa có dữ liệu.

Thay MAT_KHAU_RIENG_CUA_BAN bằng mật khẩu riêng cho ứng dụng, giống nhau ở cả hai dòng SQL. Đây là mật khẩu sẽ ghi vào config.local.php; không cần dùng mật khẩu root.

MySQL Workbench · SQL
CREATE DATABASE pixelnote
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'pixelnote_app'@'localhost'
  IDENTIFIED BY 'MAT_KHAU_RIENG_CUA_BAN';

CREATE USER 'pixelnote_app'@'127.0.0.1'
  IDENTIFIED BY 'MAT_KHAU_RIENG_CUA_BAN';

GRANT SELECT, INSERT, UPDATE, DELETE
  ON pixelnote.* TO 'pixelnote_app'@'localhost';

GRANT SELECT, INSERT, UPDATE, DELETE
  ON pixelnote.* TO 'pixelnote_app'@'127.0.0.1';

Nếu database hoặc tài khoản đã tồn tại, kiểm tra thông tin hiện có trước khi tiếp tục; không xóa để chạy lại đoạn trên. Tài khoản ứng dụng chỉ đọc và ghi dữ liệu. Việc tạo bảng dùng root trong Workbench.

Cài mới với dữ liệu mẫu

  1. Refresh mục Schemas ở thanh bên. Nhấp đúp pixelnote để tên in đậm, tức schema mặc định.
  2. Chọn File → Open SQL Script, mở C:\Projects\pixelnote\database\schema.sql.
  3. Bảo đảm schema mặc định là pixelnote. Không bôi đen riêng một đoạn; bấm nút tia sét Execute All or Selection để chạy toàn bộ file.
  4. Kiểm tra Action Output không có lỗi đỏ, rồi Refresh mục Tables.

Chạy câu sau để kiểm tra:

MySQL Workbench · SQL
SHOW TABLES FROM pixelnote;

Bản mã nguồn hiện tại có 12 bảng, gồm users, projects, versions, threads và các bảng liên quan.

Nếu chuyển dữ liệu cũ: tạo database trống và tài khoản như trên, sau đó nhập file SQL theo mục 10. Bỏ bước chạy schema.sql và bỏ lệnh tạo dữ liệu mẫu.

06

Tạo cấu hình và kiểm tra kết nối của ứng dụng

Trong VS Code, tạo file config.local.php ở thư mục gốc pixelnote, cùng cấp với thư mục public. Toàn bộ nội dung file:

File config.local.php
<?php
declare(strict_types=1);

return [
    'host' => '127.0.0.1',
    'port' => 3307,
    'database' => 'pixelnote',
    'username' => 'pixelnote_app',
    'password' => 'MAT_KHAU_RIENG_CUA_BAN',
    'secure_cookies' => false,
];

Thay port và password bằng thông tin đã xác nhận. Lưu dạng UTF-8 không BOM, không có ký tự trước <?php. Mật khẩu phải khớp với mục 05. Nếu mật khẩu có dấu nháy đơn hoặc gạch chéo ngược, cần escape đúng cú pháp SQL và PHP; để dễ thao tác, có thể dùng mật khẩu dài với chữ, số và các ký hiệu như ! @ # _.

Ubuntu WSL
/mnt/c/xampp/php/php.exe -l "$(wslpath -w "$PWD/config.local.php")"
/mnt/c/xampp/php/php.exe "$(wslpath -w "$PWD/scripts/database-status.php")"
PowerShell
& 'C:\xampp\php\php.exe' -l .\config.local.php
& 'C:\xampp\php\php.exe' .\scripts\database-status.php

Kết quả cần đạt: không có lỗi cú pháp, connected là true. Ví dụ:

Kết quả mẫu
{"host":"127.0.0.1","port":3307,"database":"pixelnote","connected":true}

connected:true xác nhận kết nối database, chưa xác nhận đầy đủ bảng, ảnh hoặc hoạt động website. Không chia sẻ file cấu hình chứa mật khẩu lên nhóm hoặc GitHub.

Thêm dữ liệu mẫu khi cài mới

Chỉ chạy sau khi đã tạo đủ bảng. Nếu nhập database từ máy cũ, bỏ qua lệnh này.

Ubuntu WSL
/mnt/c/xampp/php/php.exe "$(wslpath -w "$PWD/scripts/install.php")"
PowerShell
& 'C:\xampp\php\php.exe' .\scripts\install.php

Không thêm --local hoặc --schema. Database, tài khoản và bảng đã được tạo qua Workbench. Lệnh mặc định thêm dữ liệu mẫu; --local thuộc cơ chế instance riêng của bộ cài cũ.

Kết quả cần có dòng OK: MySQL, schema va du lieu mau da san sang.

07

Cấu hình Apache của XAMPP

Alias /pixelnote trỏ đến thư mục public. Dự án có thể nằm ngoài htdocs; Apache hỗ trợ ánh xạ này bằng Alias. [5]

Sao lưu trước khi sửa

Ubuntu WSL
for file in \
  /mnt/c/xampp/apache/conf/httpd.conf \
  /mnt/c/xampp/apache/conf/extra/httpd-pixelnote.conf
do
  if [ -f "$file" ]; then
    cp -- "$file" "$file.backup-$(date +%Y%m%d-%H%M%S)"
  fi
done
PowerShell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$files = @(
    'C:\xampp\apache\conf\httpd.conf'
    'C:\xampp\apache\conf\extra\httpd-pixelnote.conf'
)
foreach ($file in $files) {
    if (Test-Path -LiteralPath $file) {
        Copy-Item -LiteralPath $file -Destination ($file + '.backup-' + $stamp)
    }
}

Tạo file alias đầy đủ

Dùng VS Code hoặc trình soạn thảo tạo C:\xampp\apache\conf\extra\httpd-pixelnote.conf. Lưu UTF-8 không BOM. Nếu thư mục dự án khác ví dụ, thay tất cả C:/Projects/pixelnote bằng vị trí thực tế, dùng dấu /.

File httpd-pixelnote.conf
Alias "/pixelnote" "C:/Projects/pixelnote/public"

<Directory "C:/Projects/pixelnote">
    AllowOverride None
    Require all denied
</Directory>

<Directory "C:/Projects/pixelnote/public">
    Options -Indexes +FollowSymLinks
    AllowOverride None
    DirectoryIndex index.php
    Require local

    <IfModule php_module>
        php_admin_value upload_tmp_dir "C:/Projects/pixelnote/storage/tmp"
        php_admin_value upload_max_filesize "15M"
        php_admin_value post_max_size "17M"
        php_admin_flag display_errors Off
        php_admin_flag log_errors On
    </IfModule>
</Directory>

Require local chỉ cho truy cập từ chính máy chạy. “Chạy trên máy khác” ở đây là cài một bản trên máy đó; hướng dẫn này chưa cấu hình truy cập qua mạng LAN.

Nạp file alias vào cấu hình chính

Chạy một trong hai khối sau. Lệnh chỉ thêm Include khi chưa có dòng tương ứng, không thay toàn bộ httpd.conf.

Ubuntu WSL
apache_conf="/mnt/c/xampp/apache/conf/httpd.conf"
if ! grep -Eq '^[[:space:]]*Include(Optional)?[[:space:]]+"?conf/extra/httpd-pixelnote\.conf"?[[:space:]]*$' "$apache_conf"; then
  printf '\nInclude "conf/extra/httpd-pixelnote.conf"\n' >> "$apache_conf"
fi
PowerShell
$apacheConf = 'C:\xampp\apache\conf\httpd.conf'
$pattern = '(?m)^[ \t]*Include(?:Optional)?[ \t]+"?conf/extra/httpd-pixelnote\.conf"?[ \t]*\r?$'
$content = [System.IO.File]::ReadAllText($apacheConf)
if ($content -notmatch $pattern) {
    $line = [Environment]::NewLine + 'Include "conf/extra/httpd-pixelnote.conf"' + [Environment]::NewLine
    $utf8 = New-Object System.Text.UTF8Encoding($false)
    [System.IO.File]::AppendAllText($apacheConf, $line, $utf8)
}

Nếu báo Permission denied hoặc Access denied khi ghi file XAMPP, mở trình soạn thảo hoặc PowerShell trên Windows bằng Run as administrator để thực hiện phần cấu hình này. sudo trong Ubuntu không thay thế quyền quản trị Windows.

Kiểm tra cú pháp

Ubuntu WSL
/mnt/c/xampp/apache/bin/httpd.exe -t -f "C:/xampp/apache/conf/httpd.conf"
PowerShell
& 'C:\xampp\apache\bin\httpd.exe' -t -f 'C:\xampp\apache\conf\httpd.conf'

Chỉ tiếp tục khi có Syntax OK. Nếu lỗi, sửa đúng file và dòng được báo rồi kiểm tra lại. Nếu cần quay lại, khôi phục bản sao lưu httpd.conf và alias cũ vừa tạo, sau đó kiểm tra lại cú pháp.

08

Mở website và kiểm tra chức năng

  1. Mở XAMPP Control Panel từ Start của Windows.
  2. Bấm Start ở dòng Apache. Nếu Apache đã chạy, bấm Stop rồi Start để nạp cấu hình mới.
  3. Không bật dòng MySQL của XAMPP cho dự án này.
  4. Mở trình duyệt Windows tại http://localhost/pixelnote/.

Có thể mở Control Panel từ terminal:

Ubuntu WSL
/mnt/c/xampp/xampp-control.exe
PowerShell
Start-Process -FilePath 'C:\xampp\xampp-control.exe' -WorkingDirectory 'C:\xampp'

Lệnh mở bảng điều khiển để bạn trực tiếp bấm Start hoặc Stop. Nếu terminal Ubuntu đang chờ ứng dụng, mở thêm một tab terminal để làm việc.

Tài khoản mẫu khi cài mới

Vai tròEmailMật khẩu
Chủ dự án mẫudesigner@pixelnote.testDesigner123!
Người góp ýreviewer@pixelnote.testReviewer123!
Người chỉ xemviewer@pixelnote.testViewer123!

Các tài khoản trên chỉ áp dụng nếu đã tạo dữ liệu mẫu. Khi chuyển dữ liệu cũ, sử dụng tài khoản cũ.

Kiểm tra sau cài đặt

  • Đăng nhập, tạo một dự án thử và tải ảnh PNG hoặc JPEG.
  • Thêm người góp ý; xác nhận tài khoản chỉ xem không tạo được góp ý.
  • Tạo góp ý đầu tiên ở một phiên bản mới: hiển thị số 1; góp ý tiếp theo hiển thị số 2.
  • Tải phiên bản mới: góp ý cũ vẫn thuộc phiên bản cũ; góp ý đầu tiên của phiên bản mới bắt đầu từ 1.
  • Chọn hai phiên bản khác nhau để so sánh và kéo thanh chia. Với ảnh khác tỷ lệ, kiểm tra giao diện so sánh cạnh nhau.
  • Tải lại trang, đăng nhập lại nếu cần và xác nhận dữ liệu đã lưu.

Đây là các bước tự kiểm tra trên máy mới, không phải kết quả đã được xác nhận trên máy đó.

09

Bật và dừng khi sử dụng hằng ngày

Không chạy lại bước tạo database, nhập schema hoặc tạo dữ liệu mẫu mỗi lần mở website.

Khi cần chạy

  1. Kiểm tra dịch vụ Oracle MySQL đang Running. Nếu đã đặt tự khởi động cùng Windows thì thường không cần bật lại.
  2. Mở XAMPP Control Panel và Start Apache.
  3. Truy cập http://localhost/pixelnote/.

Có thể kiểm tra kết nối từ thư mục dự án:

Ubuntu WSL
/mnt/c/xampp/php/php.exe "$(wslpath -w "$PWD/scripts/database-status.php")"
PowerShell
& 'C:\xampp\php\php.exe' .\scripts\database-status.php

Khi dùng xong

Bấm Stop Apache trong XAMPP. Khi nút trở về Start, tải lại website để xác nhận không truy cập được. Dừng Apache sẽ dừng cả các website khác đang dùng chung Apache đó. MySQL vẫn chạy để Workbench có thể tiếp tục kết nối. [1]

Đóng tab trình duyệt hoặc thoát VS Code không đồng nghĩa với dừng Apache. Bấm Quit trong XAMPP Control Panel cũng không nên dùng thay thao tác Stop Apache.

Nếu muốn dừng cả MySQL, mở PowerShell trên Windows bằng Run as administrator, dùng đúng tên dịch vụ:

PowerShell Windows · Run as administrator
Stop-Service -Name 'MySQL80'
Get-Service -Name 'MySQL80'

Lần sau khởi động lại:

PowerShell Windows · Run as administrator
Start-Service -Name 'MySQL80'
Get-Service -Name 'MySQL80'

Dừng dịch vụ không xóa database, nhưng sẽ ngắt ứng dụng và Workbench dùng chung dịch vụ đó. Hãy hoàn tất thao tác đang làm trước khi dừng.

10

Chuyển dữ liệu từ máy cũ sang máy mới

Bạn cần cả bản sao database và thư mục ảnh. ZIP mã nguồn phát hành không chứa database cá nhân, config.local.php hay ảnh đã tải lên.

Trên máy cũ

  1. Dừng Apache để không có thay đổi dữ liệu trong lúc sao lưu; giữ MySQL chạy.
  2. Mở Workbench và kết nối đúng instance đang chứa pixelnote. Với cách cài cũ của dự án, đó có thể là instance riêng ở cổng 3307.
  3. Chọn Server → Data Export → chọn schema pixelnote và toàn bộ bảng.
  4. Chọn Dump Structure and Data và Export to Self-Contained File. Ghi file SQL vào nơi bạn tìm lại được.
  5. Bấm Start Export và chờ hoàn tất, kiểm tra không có lỗi. [6]
  6. Sao chép toàn bộ thư mục storage/uploads của dự án. Đặt bản sao SQL và thư mục ảnh cùng một bộ sao lưu.

Nếu MySQL trên máy cũ đang dừng và dùng .runtime/my.ini, cần khởi động đúng instance cũ trước khi xuất. Việc sao chép thẳng thư mục .runtime/mysql-data không phải cách chuyển dữ liệu trong hướng dẫn này.

Trên máy mới

  1. Chuẩn bị mã nguồn sạch và tạo thư mục storage như mục 02 và 04.
  2. Kết nối Oracle MySQL của máy mới bằng Workbench. Tạo database pixelnote trống và tài khoản ứng dụng theo mục 05.
  3. Bỏ bước chạy schema.sql. Chọn Server → Data Import → Import from Self-Contained File, chọn SQL vừa xuất.
  4. Chọn Default Target Schema là pixelnote, bấm Start Import và kiểm tra kết quả. Chỉ nhập vào database mới trống; file sao lưu có thể chứa lệnh thay thế bảng. [6]
  5. Chép các file ảnh từ bản sao storage/uploads vào storage/uploads của dự án mới, giữ nguyên tên file.
  6. Tạo config.local.php theo tài khoản và cổng của máy mới. Không dùng nguyên mật khẩu hoặc đường dẫn cấu hình máy cũ nếu đã thay đổi.
  7. Bỏ lệnh thêm dữ liệu mẫu. Tiếp tục cấu hình Apache và mở web.
  8. Đăng nhập bằng tài khoản cũ, mở một vài ảnh, phiên bản và góp ý để xác nhận dữ liệu.

Không chép .runtime, file PID hoặc phiên đăng nhập storage/sessions sang máy mới trong quy trình này. Không cần giữ nguyên ổ E hay đường dẫn cũ; cần sửa alias Apache theo vị trí mới.

Kiểm tra cổng MySQL từ phía Windows

Dùng cổng thực tế của server. Khi ở WSL, gọi PowerShell Windows để tránh nhầm localhost giữa Linux và Windows.

Ubuntu WSL
powershell.exe -NoProfile -Command 'Test-NetConnection -ComputerName 127.0.0.1 -Port 3307 -InformationLevel Quiet'
PowerShell
Test-NetConnection -ComputerName 127.0.0.1 -Port 3307 -InformationLevel Quiet

True chỉ cho biết cổng nhận kết nối TCP. Muốn xác nhận đúng database và tài khoản ứng dụng, chạy database-status.php.

Đọc log gần nhất

Ubuntu WSL
tail -n 40 storage/logs/php.log
tail -n 40 /mnt/c/xampp/apache/logs/error.log
PowerShell
Get-Content -LiteralPath .\storage\logs\php.log -Tail 40
Get-Content -LiteralPath 'C:\xampp\apache\logs\error.log' -Tail 40

Nếu file log chưa tồn tại, hệ thống có thể chưa ghi lỗi vào đó. Khi gửi lỗi để hỗ trợ, gửi thông báo liên quan và che mật khẩu; không gửi toàn bộ config.local.php hoặc .runtime/install.json.

Nếu cổng 80 bận, kiểm tra ứng dụng chiếm cổng trước; không dừng ngẫu nhiên tiến trình khác. Nếu Apache đã được cấu hình dùng cổng 8080, URL phải là http://localhost:8080/pixelnote/.

Danh sách xác nhận và tài liệu tham khảo

  • Đã xác nhận đúng thư mục dự án và đúng PHP của XAMPP.
  • Đã bật đủ PDO, pdo_mysql, mbstring và fileinfo.
  • Workbench kết nối đúng Oracle MySQL và xác nhận đúng cổng.
  • Có database pixelnote và các bảng; tài khoản ứng dụng có quyền cần thiết.
  • database-status.php trả connected:true.
  • Apache báo Syntax OK và đang chạy.
  • Truy cập được website, đăng nhập và tải ảnh thành công.
  • Dữ liệu vẫn còn sau khi dừng và bật lại.
  • Đã biết cách sao lưu cả SQL và storage/uploads.

Hướng dẫn này áp dụng cho bản PixelNote-XAMPP-MySQL của dự án, với các file scripts/install.php, scripts/database-status.php, config.example.php và cấu hình alias trong scripts/xampp-common.ps1. Cập nhật ngày 30 tháng 10 năm 2026.
